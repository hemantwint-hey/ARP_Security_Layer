2. The 8-Step Sanitization Pipeline Verified

1 Jackson 3 Deserialization: Safely reads raw incoming JSON into TransactionCompletedInboundEvent.
2 Idempotency Guard: Checks processedEventRepo.existsByEventId() to drop duplicate deliveries.
3 Identity Vault Token Resolution: Mints or retrieves cached R789-xxxx ARP token via ArpTokenResolverService; skips if user opted out.
4 Free-Text PII Scrubbing: Neutralizes phone numbers, emails, accounts, and prompt-injection keywords via PiiScrubber.
5 Data Minimization: Transforms timestamps into WEEKDAY_NIGHT and rupee amounts into MEDIUM_500_2500.
6 HMAC Merchant Clustering: Computes deterministic salted HMAC-SHA256 hash so AI can detect recurring merchants without seeing raw store names.
7 Targeted Partition Publishing: Sends event to arp.sanitized.transaction partitioned by arpToken.
8 Audit Trail & Commit: Writes SHA-256 event hash to PrivacyAuditLog and marks GatewayProcessedEvent in a single transaction.

3. Security & Architecture Checklist

  • Retry & Dead-Letter Safety: Configured with @RetryableTopic(attempts = "4", backOff = @BackOff(delay = 1000, multiplier = 2.0, maxDelay = 10000)), excluding unrecoverable NPEs and validation errors.
  • Deterministic Ordering: Using arpToken as the Kafka partition key guarantees all events for a given customer arrive in order at the AI service.
  • Non-Reversible Source Tracing: Inbound eventId is replaced by a one-way SHA-256 hash (sourceEventHash) preventing reverse lookup of internal banking records.
  • Zero Compiler Warnings: Standardized on Spring Boot 4.1.2, Jackson 3 (tools.jackson.databind.*), and Java 17 records.
